# 卫生接驳

本地合成业务资料。人名标识、去向、机构和观测均为虚构，不接入外部系统。

## 输入约定

`data/supplies.json` 以表名组织记录；`data/fields.json` 列出字段及该资料出现的值类型。

日期为 2026-11-24，时刻都是当地时间。`trips` 的一行是一项往返需求；`alt_arrival` 是已同意使用的备选到院窗口。上下车的时刻在窗口内则符合约诊；换乘步行时间不超过 `max_walk_min`，而且要能接续后段班次。`locked` 给出不可改签的载运承诺，由 `reservations` 记录其已确认的双程载运。`scenarios` 给出完整需求组合，列中的请求都属于当次需求；不赋予情景概率。服务底线按各社区在每个指定情景中满足双程需求的比例，分母无需求时标为不适用。
`legs` 用始发、终点、车辆、开到时刻和可用座位描述可查验的方案；上车占用一趟连续行程经过的每个区段。`run` 标识同一车辆连续开行的同一趟，不能因线路代码不同重复计算；不同运行若占用同车的重合时间不能同批使用。普通座不能替代轮椅位，普通客也不能挪用轮椅位。`walks` 是允许的步行换乘连接。方案 `BASE` 表示维持旧线，`VIA` 为绕行，`JOIN` 为共享接驳。切换或改约仅在本地调度册登记，不连接真实医院或车辆。

## 资料检查

在 Linux 上使用 Python 3.11 及标准库，无需安装第三方包。运行 `python3 -m unittest discover -s tests -v` 检查表字段、类型和关键关联。当前仓库只包含业务来源资料及检查，尚无分析结果或业务操作入口。
