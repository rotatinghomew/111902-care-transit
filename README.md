# 卫生接驳

本地合成业务资料。人名标识、去向、机构和观测均为虚构，不接入外部系统。

## 输入约定

`data/supplies.json` 以表名组织记录；`data/fields.json` 列出字段及该资料出现的值类型。

日期为 2026-11-24，时刻都是当地时间。`trips` 的一行是一项往返需求；`alt_arrival` 是已同意使用的备选到院窗口。上下车的时刻在窗口内则符合约诊；换乘步行时间不超过 `max_walk_min`，而且要能接续后段班次。`locked` 给出不可改签的载运承诺，由 `reservations` 记录其已确认的双程载运。`scenarios` 给出完整需求组合，列中的请求都属于当次需求；不赋予情景概率。服务底线按各社区在每个指定情景中满足双程需求的比例，分母无需求时标为不适用。
`legs` 用始发、终点、车辆、开到时刻和可用座位描述可查验的方案；上车占用一趟连续行程经过的每个区段。`run` 标识同一车辆连续开行的同一趟，不能因线路代码不同重复计算；不同运行若占用同车的重合时间不能同批使用。普通座不能替代轮椅位，普通客也不能挪用轮椅位。`walks` 是允许的步行换乘连接。方案 `BASE` 表示维持旧线，`VIA` 为绕行，`JOIN` 为共享接驳。切换或改约仅在本地调度册登记，不连接真实医院或车辆。

## 资料检查

在 Linux 上使用 Python 3.11 及标准库，无需安装第三方包。运行 `python3 -m unittest discover -s tests -v` 检查表字段、类型和关键关联。当前仓库只包含业务来源资料及检查，尚无分析结果或业务操作入口。

## 分析入口

分析代码在 `shuttle/`，与资料目录隔离；隔离模式下用包装脚本运行（`-I` 不读 `PYTHONPATH` 和当前目录）：

```
python3 -I analyze.py <子命令> [--data data/supplies.json]
```

| 子命令 | 用途 |
| --- | --- |
| `scenarios` | 逐方案逐情景枚举全部极大可行排班，含每个需求的可达、挤出、改约延误及原因代码 |
| `compare` | BASE/VIA/JOIN 三方案服务量、社区底线、末班返程与稳健排班对照 |
| `robust --plan P` | 出车前可签发的固定留座：同一份 run 选择须对全部指定情景守得住 |
| `last-return [--plan P]` | 逐需求最晚返程与逐社区“丧失末班返程”清单，不做总体平均 |
| `fillins --plan P` | 固定留座之外、只能随现场确认递补或暂缓的需求 |
| `drilldown --trip T --plan P` | 单需求路径级钻取：站点不通、步行超限、时间窗不合、接续不合、轮椅位不足、运力挤占 |
| `audit [--plan P]` | 车辆不可用生效后的留座核对、失效安排与改约/暂缓建议（默认审公告方案） |
| `held [--trip T]` | 查询现在仍给谁留座，以及某需求的改约状态 |
| `report --output reports/analysis.html [--outage] [--text]` | 单文件 HTML（差异可点开）或纯文本报告 |

加 `--outage` 时套用 `dispatch_log` 里的车辆不可用窗口；加 `--format json` 可取得机读结果。

### 判定约定（与录入约定配套）

- 一项预约是一个往返需求，去程与返程同时走通才算服务；需求按 `scenarios` 的完整组合分别分析，不拼接各情景最大数，不赋概率。
- 窗口端点包含；跨 run 接续与步行换乘都要求后段发车**严格晚于**前段到达（零缓冲不可接续），步行时长计入接续时钟且不得超过 `max_walk_min`。
- 备选到院窗口仅在 `alt_arrival` 已同意时可用，输出标记为改约延误；未同意的新窗口不视为接替，锁定原约不会被当作主动取消。
- 容量按 `(run, seq)` 区段登记，轮椅位与普通座位分账、互不替代；同一 run 跨线或经多站只产生一份区段容量，同车时间重合的 run 暴露为冲突。
- `locked` 需求先占 `reservations` 中已确认的双程容量；不可兑现时记为承诺违约，而不是悄悄重排。
- 社区底线按情景内双程满足比例核算，分母无需求标为不适用；稳健排班必须在每个情景都不破容，且只保留全情景极大组合。
- 收缩审计区分三类对象：继续留座、原接送已失效（历史公告不得批准其继续）、仅可提出改约建议或告知暂缓。

### 本资料的关键结论（2026-11-24）

- BASE 旧线：常态 3/3 全服务且两社区达标；复诊增多 3/4，T4 因柳桥 09:55 后无班次而不可达，柳桥仍恰好 50% 达标。
- VIA 绕行：常态只能 2/3，T2 与 T3 在 D2#1 普通座互斥，两个极大排班分别破柳桥或梧桐底线；复诊增多存在 3/4 且双底线达标的取舍，代价是挤出 T2（T2 仅能走已同意的 10:00 备选窗口，属改约延误）。
- JOIN 共享接驳：F1 到梧桐东 08:36 后步行 4 分钟到梧桐恰为 08:40，与 B1 发车零缓冲不可接续，柳桥 T2/T4 两情景均不可达、底线皆破，并丧失末班返程。
- 出车前稳健安排：BASE 可固定 T1/T2/T3；VIA 只能在 T2、T3 之间二选一并各自成表；JOIN 仅能固定 T1/T3，柳桥需求只能现场递补。
- V2 在 08:00-10:30 不可用后：三方案的柳桥去程 run（B2/D1/F1）均停用，O1（T1，V1 双程）继续留座且锁定承诺不受影响；柳桥需求无已同意的替代窗口，处置为告知暂缓而非伪造改约。
